# 周报 · SWE-agent 训练全流程(Ascend / ≤8B)

**目标**:在 Ascend 上跑通 "自产数据 → SFT 冷启动 → RL → 评测" 全链路,并保证每个环节可信、可复现。

## 本周进展

1. **端到端跑通前半条链路**:自产 SFT 数据(GLM teacher)→ 8B 冷启动 SFT 训练成功(loss 0.69→0.377,8 卡 verl FSDP),HF 模型已产出、可直接评测。
2. **RL 奖励池 = 1864 条可信实例**(复检完成):用修好的打分器对整池重做 gold→1 ∧ buggy→0 双向验证后定稿(候选 ~2000 收紧到 1864,剔除子串假通过 + 测试没跑起来的)。这是已验证的可用量,非候选量。
3. **审计并修复打分管线**:发现 resolve 打分路径有系统性 bug(详见难点),用多角度对抗式审计定位并修复 **6 个问题**;修复后验证 scorer 能正确区分对错(真补丁 resolve 率从虚高的 98.6% 回到现实的 82%)。

## 难点与风险

1. **打分管线此前有 bug(本周核心)**:模型补丁打分路径形同虚设——空补丁也被判"已解决",导致此前的 resolve 标签不可信。已修复+验证;**残留**:需用修好的 scorer 重新打分,才能得到可信的数据规模。
2. **数据可用规模偏低**:主因是 SWE-smith 数据的 git 历史泄漏(结构性)+ 上述打分可信度问题。策略:**先修可信度、再走量**,不在不确定性上提前重押。
3. **冷启动数据偏小**:当前 430 条定位为"流程验证 + RL 冷启动种子",模型质量主要靠 RL 阶段拉。

## 下一步

1. 用修好的打分器**重新验证 SFT 数据 + RL 池**(gold→1 ∧ buggy→0 复检)→ 拿到可信的可用规模(SFT 与 RL 池都待此结果定稿)。
2. 数据走量(更多筛查 + 受控 GLM 生成,严格控成本)。
3. 在 Ascend 上把 RL 训练端到端跑通(用复检后的干净池 + 8B 冷启动种子)。
4. 闭合评测:模型在评测体系上测分,打通 训练→推理→评测。
